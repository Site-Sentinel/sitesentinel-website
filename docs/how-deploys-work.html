Site Sentinel / Website editing guide

From your request to the live website

Open your cloned website folder in desktop Codex and choose Local. Review changes on your computer, then share a Netlify preview. Publish only after you approve.

Your approval is the publishing gate. Asking for a change allows work on a preview. It does not approve a production release.

Prepare a preview

  1. 1

    Create a branch

    Fetch the latest origin/main. Create a local feature branch to hold changes separately from production.

  2. 2

    Make your change

    Read the repository instructions and make the requested edits. Run pnpm dev and review at localhost:4330.

  3. 3

    Check the result

    Run pnpm check and pnpm build. Inspect the page at desktop and phone widths.

  4. 4

    Push and open a PR

    A commit records the edits. A push sends the branch to GitHub. A pull request (PR) proposes merging it into main.

GitHub checks and Netlify build the preview↓

Review before publishing

  1. 5

    Open the preview

    Wait for successful checks. The assistant gives you the actual Netlify preview and PR links. Review on desktop and phone.

  2. 6

    You approve

    Approve publishing this version explicitly. If you request more edits, review the updated preview before approving again.

  3. 7

    Merge into main

    After approval, merge the PR. Netlify builds and publishes the production version from main.

  4. 8

    Confirm it is live

    Verify the production deployment matches the merged commit, then open the deployed page. Report the confirmed production link.

Something needs fixing?

Continue on the same branch and PR. Push the correction, wait for checks and a new preview, then review again. A failed check means fix the cause before merging.

Set up the safeguards once

An administrator must protect main and require PR checks. Netlify must have Deploy Previews enabled and use main for production. Written instructions alone do not enforce these settings.
